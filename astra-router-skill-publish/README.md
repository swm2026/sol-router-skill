# Astra Router

对外统一叫 astra-router v2。内部使用 GPT-6 Luna、Sol、Astra 的最小充分路由，在满足验收与安全约束的前提下，减少不必要的模型调用和重复上下文。

| 任务 | 默认路线 |
| --- | --- |
| R0：机械、低风险小任务 | Luna |
| R1：目标明确的开发、调试和调查 | Sol |
| R2：需要单独拆解或解决执行顺序 | Sol → Sol/Luna |
| R3：架构取舍、方向或重大风险决策 | Astra → Sol |
| R4：后果重大且确有争议 | Sol 挑战分析 → Astra → Sol |

普通工程任务允许 Sol 自行规划，不因“涉及代码”自动调用 Astra。Astra 只处理后果重大的判断；不要求每个任务都调用多个模型。

模型映射：机械执行 → `gpt-6-luna`；工程执行和单独规划 → `gpt-6-sol`；重大决策 → `gpt-6-astra`。

## 安装与调用

```powershell
npx.cmd skills add https://github.com/swm2026/sol-router-skill --skill astra-router -g
```

非 Windows 环境可用 npx。安装位置取决于安装器所选目标代理，请确认安装到 Codex 的技能目录。仓库地址与技能调用名可以不同。

```text
$astra-router 修复这个已定位的错误，并完成相关验证。
```

仅显式调用。更新旧版本后，检查目标技能是否已更新；本技能不会修改其他项目的 AGENTS.md。

## 减少消耗的机制

- R0/R1 默认不调用独立规划大脑；R2/R3 通常只调用一个大脑。
- 父会话已是合适角色时不再创建重复代理；极小任务避免昂贵交接。
- 执行器调查后继续实施；证据一次传递，后续只传变化。
- 复用有效决策，不进行例行二次审批；普通失败由执行器处理。
- 按需加载参考文件，限制无关日志与长篇汇报，软性控制输入输出长度。
- 记录真实角色、调用与恢复次数；用量不可见时不声称节省百分比。

详见 [用量评估方法](skills/astra-router/references/efficiency.md)。软长度目标不能限制隐藏推理或账单；技能不能切换父会话模型。只有格式验证不能证明实测节省。

## 权限与兼容性

规划结论不会扩大授权；保留项目的账户、broker-write、runtime_guard 等边界。工具和模型可用性以当前环境为准；不把替代模型冒充成指定模型。常规恢复复用已有授权，不增加重复确认。
